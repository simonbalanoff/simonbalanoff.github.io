The control problem

The rocket must move from its launch position to a movable landing platform while managing thrust, orientation, and fuel. The controller receives noisy telemetry rather than simply acting on an exact state.

I built the simulator to explore the interaction between state estimation, flight-phase logic, and feedback control in a visible, testable environment.

Guidance & estimation

Estimate the flight state

A NumPy Kalman filter jointly estimates horizontal position, rocket-bottom height, both velocities, attitude, and angular velocity. The model tracks how position and velocity change together and handles angles that cross from 359 degrees to zero. It also tracks uncertainty in the estimates, using the Joseph update to maintain the filter’s covariance calculation.

Change behavior as the mission progresses

Autopilot flight phases
PhaseController behavior
LaunchApply full thrust and lean toward the landing zone.
AscentControl climb rate and steer laterally.
CoastReduce thrust as the rocket approaches apogee.
DescentFollow a descent-speed target based on altitude.
TerminalCorrect lateral error and reduce speed for touchdown.

Close the feedback loop

A proportional-derivative controller computes attitude torque from angular error and rate. Throttle follows the difference between the reference descent rate and estimated vertical velocity, with correction for tilt.

Simulation decisions

Fixed 120 Hz physics (120 updates per second): dynamics and guidance use a fixed timestep, independent of the rendering speed. Long frames are capped at 100 milliseconds to prevent unstable catch-up.

Contact-based landing detection: a successful landing requires actual contact with the deck, an approach speed below 30 pixels per second, an attitude within 10 degrees of upright, and the rocket body inside the deck edges. Ground contact counts as failure.

Inspectable flight records: interactive and headless missions can record telemetry, commands, controller targets, fuel use, and final outcomes to CSV. Analysis plots expose where the controller changes phases and how closely it follows its targets.

Validation & limits

Automated tests run the simulation without opening its graphical interface. They cover complete missions on both sides of the launch pad, different elevations, landing geometry, fuel limits, and angle filtering across zero. GitHub Actions runs the suite on Python 3.10, 3.12, and 3.13.

Optional controller tuning uses differential evolution across training missions. The baseline is retained if a candidate does not improve the training score; separate holdout missions are reported without influencing selection.

This is a simplified 2D guidance demonstrator. Distances use pixels, fuel uses arbitrary units, and some platform placements exceed the available fuel or thrust. It is not a real-world flight model.
